# تقرير النسخة المستقلة المستقرة — Flotex EGP

**تاريخ التحقق:** 15 نوفمبر 2026
**النطاق:** مشروع Manus Mobile مستقل من ملفات ZIP؛ لا نشر عام ولا بيانات مالية حقيقية.

## النتيجة

أُنشئ مشروع Expo Mobile مستقل داخل Manus، ونُقل إليه مصدر التطبيق مع قفل الحزم والأصول، مع الاحتفاظ بمعرف Android/iOS المستقل الذي أنشأته مساحة Manus. بقي ZIP ومصدر الأصل كما هما. أُنشئ مخطط قاعدة بيانات منفصل؛ طبّق الترحيل 47 migration وأصبح يحوي 59 جدولًا. تأكد أن جداول المستخدمين والمحافظ والمعاملات وطلبات الكوين وخطط الادخار كلها تحتوي صفر سجلات. لم تُوصل النسخة بقاعدة الأصل ولم تُنقل إليها بيانات أو أرصدة.

المعاينة داخل Manus جاهزة على Expo Web، إذ استجاب Metro عبر HTTP 200 وردّ API على `/api/ready` بحالة جاهز واتصال قاعدة بيانات. افتح مشروع **Flotex EGP — النسخة المستقرة المستقلة** من مساحة المشاريع ثم اختر Preview؛ لا تحتاج إلى تنزيل ZIP للتعديل أو الفحص.

## أهم الإصلاحات

- إزالة تحديثات React المتزامنة في تأثير `useEffect` من شاشة مراسلة المستخدم ولوحة مراسلات الإدارة. أصبحت فئة المحادثة والاختيار متزامنين مع معاملات المسار من دون التصيير المتتابع المسبب لمشكلة Lint.
- فصل تنسيق قيمة الجنيه عن لاحقة `ج.م` وإزالة تكرار الوحدة في الرصيد وملخص الادخار على الشاشات الصغيرة، مع اختبار وحدة جديد، ومن دون تغيير هيئة الأزرار أو وظائفها.
- إضافة حدود تركيز ذهبية لحقول الدخول والتسجيل عند تحديدها، مع إبقاء أبعاد الأزرار ومواقعها ووظائفها دون تغيير.
- فصل محادثات الحساب والمعاملات الخارجية والحساب المجمّد إلى فئات مستقلة، مع حفظ استعلام الطلبات القديم المتوافق عند عدم تمرير فئة.
- إضافة OTP أحادي الاستخدام من البريد المسجل قبل تغيير كلمة المرور، وإبطال الجلسات بعد التغيير، وعدم تسجيل كلمة المرور كنص صريح. أصبح حد إعادة الإرسال 3 رموز لكل بريد/هاتف خلال 15 دقيقة ذريًا بقفل MySQL ومفتاح HMAC، مع اختبار تكامل للطلبات المتزامنة.
- عند فشل تسليم البريد، تُحذف محاولة الرمز وتُحرر حصة إعادة الإرسال حتى يمكن للمستخدم المحاولة مجددًا؛ اختُبر ذلك بمرسل SMTP وهمي يفشل ثم ينجح.
- إضافة بصمة HMAC مطبّعة وفهرس فريد للرقم القومي، تشمل مسار التوثيق وتغيير البيانات الإداري، لمنع الحسابات المكررة والسباقات دون كشف بيانات الحساب الآخر.
- تسجيل آخر فتح وإصدار التطبيق وبناءه في ملف العميل عند ورودها من التطبيق، وتنظيم أقسام لوحة الإدارة مع بقاء شكل الأزرار ووظائفها.
- الحفاظ على شاشة تأكيد التسجيل العابرة: لا تظهر إلا بعد إنشاء الحساب وتثبيت الجلسة، وتعرض البيانات التي أُنشئت فعليًا مرة واحدة، مع النسخ والتنبيه ومسح القيم المؤقتة بعد الاستخدام.
- مراجعة حواجز صرف الادخار: مهلة الإدارة، صرف تلقائي بعد المهلة في الإنتاج، التكرار الآمن، حجز التمويل، وسلوك نقص الرصيد؛ لم تُنشأ جدولة إنتاجية في النسخة غير المنشورة.
- إضافة الأمر الاختياري `pnpm test:coin-integration` لاختبار الكوين على قاعدة اختبار فارغة محددة الاسم وبصمة DSN؛ يظل منفصلًا عن الاختبارات العامة ويزيل سجلاته الاصطناعية فقط.

## نتائج الفحوص

| الفحص | النتيجة |
|---|---|
| `pnpm check` | ناجح؛ لا أخطاء TypeScript |
| `CI=true pnpm lint` | ناجح؛ لا أخطاء Lint. ظهرت تحذيرات إعداد pnpm قديم وتحذير Node عن نوع ES module في `eslint.config.js`، دون تعطيل الفحص |
| `pnpm test` بقاعدة loopback محلية | **67 ملفًا، 435 اختبارًا ناجحًا، 0 فاشل** |
| اختبار التكامل المالي `pnpm test:coin-integration` | ناجح للشراء والبيع والإرسال والحجوزات والدفتر والتكرار والتفاصيل الإدارية وإشعارات قاعدة البيانات؛ أزيلت بيانات الحسابات الاصطناعية واستُعيد إعداد السعر والخزينة السابقان |
| `CI=true pnpm build` | ناجح؛ Expo Web ونسخة خادم API بُنيتا، وعُرضت 44 صفحة ثابتة |
| قاعدة Manus الجديدة | 59 جدولًا؛ 47 سجل ترحيل؛ صفر مستخدمين/محافظ/معاملات/طلبات كوين/خطط ادخار |
| API `/api/ready` وExpo Preview | كلاهما يستجيب بنجاح؛ الخادم متصل بقاعدة النسخة الجديدة |

التحذير وقت بناء الويب من `expo-notifications` يخص أن الاستماع لتغيّر Push Token غير مدعوم على الويب؛ لذلك لا يُعدّ إثباتًا لوصول إشعارات Push على جهاز حقيقي.

## ما لم يُختبر أو لم يُنفّذ

- لا يوجد ملف APK/AAB حتى الآن. القالب الرسمي يفرض إنشاء إصدارات Android/iOS من لوحة Manus، لا من Sandbox. يلزم ربط اعتماد Expo في Dashboard (من دون إرسال رموزه في المحادثة). كما يحتاج الإصدار الإنتاجي إلى عنوان API ثابت صالح؛ لم يُنشر الخادم، التزامًا بعدم النشر خلال التحقق.
- لم يُثبت تثبيت التطبيق/مسح QR عبر Expo Go على هاتف فعلي؛ ربط Expo Go يتطلب الحساب نفسه الذي رُبط باللوحة.
- لم يُفتح منتقي الصور أو الكاميرا على Android فعليًا؛ اجتازت الوظائف اختبارات الكود فقط (منتقي الصورة 10 اختبارات وتغيير الهاتف تكامل واحد). لا تُعد معاينة الويب إثباتًا لتوافق الكاميرا الأصلية.
- لم تُرسل رسالة OTP إلى Gmail فعلي؛ الاختبار استخدم مرسلًا وهميًا. الاعتمادات محمية عن الشيفرة وحزمة الهاتف. وبما أن اعتماد Gmail أُرسل نصًا في المحادثة، يُنصح بإلغائه في Google وإنشاء App Password جديد قبل تفعيل إرسال البريد الفعلي، ثم استبداله من نموذج الأسرار المحمي في Manus.
- لم تُرسل Push Notifications إلى جهاز؛ اختُبرت إشعارات قاعدة البيانات فقط.
- لم تُفعّل مهمة Heartbeat أو يُجرَ صرف عوائد حقيقي. يبدأ تسجيل المهمة بعد نشر خادم الإنتاج ووجود خطة ادخار نشطة؛ راجع `CRON_SETUP.md`.
- لم يحدث شراء أو بيع أو تحويل أو تعديل رصيد على أموال/حسابات حقيقية.

## حدود النشر والبيانات

النشر العام، بناء APK/AAB، إنشاء مهمة Heartbeat تشغيلية، وترحيل بيانات الحسابات الأصلية كلها خطوات مستقلة لم تُنفّذ. تتطلب أي منها موافقة/إعدادًا مناسبًا، ولا تمثل نجاح الاختبارات أو جاهزية المعاينة موافقة على تشغيل نظام مالي حي. لا تُدخل بيانات سرية أو صور هوية حقيقية في قاعدة هذه النسخة التجريبية.
