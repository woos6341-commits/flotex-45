# تشغيل أثير على المدى الطويل

لا يوجد تطبيق يمكن ضمان عدم توقفه مدى الحياة. استمرار أثير يحتاج استضافة وقاعدة بيانات ونطاقًا ثابتًا وصيانة ونسخًا احتياطية يمكن استعادتها. ما جرى في هذا التحديث هو تحسين الكود وقابلية اكتشاف الأعطال، وليس تفعيل خدمة مراقبة أو ضمان توافر.

## ما أصبح موجودًا

`/api/health` يعرض حالة عملية الخادم ومعرّف تشغيلها ووقت البدء، و`/api/ready` ينفذ قراءة فعلية من قاعدة البيانات ويرجع 503 عند عدم جاهزيتها أو تجاوز المهلة. لا يعرض أي DSN أو بيانات عملاء. يستقبل الخادم SIGTERM وSIGINT وينتظر الطلبات الحالية قبل إنهاء العملية ضمن مهلة 15 ثانية؛ حالات الإيداع والسحب وتعديل الرصيد تبقى محفوظة في قاعدة البيانات ومعرّفات العمليات تمنع تكرارها بعد إعادة المحاولة.

أضيفت مهلة واضحة لطلبات API من الهاتف ورسالة مفهومة عند انقطاع الشبكة. أصلح تصحيح محفوظ في `patches/react-native-css-interop@0.2.1.patch` عطل معاينة Metro عند تحديث CSS بسبب اختلاف صيغة الحدث في Metro/Expo 57. لا يعتمد الإصلاح على تعديل مؤقت في node_modules ولا يتطلب ترقية إصدارات Expo.

## إعدادات ما زالت لازمة للإطلاق

آخر فحص للاستضافة المنشورة يعرض `on_demand`. لم يُفعّل وضع تشغيل دائم، ولم تُغيّر استضافة سبق رفضها تلقائيًا. قد يحدث بدء بارد عند الخمول؛ حالة عملية التطوير في Sandbox لا تثبت استمرارية إصدار العملاء المنشور.

يوفر المشروع المُدار عنوان API للهاتف تلقائيًا في المعاينة والبناء. تحقق عند إطلاق APK أنه يستخدم خادم الإنتاج، ولا تحفظ عنوان port-Sandbox المؤقت كعنوان دائم. إذا نُقل التطبيق إلى استضافة مستقلة مستقبلًا، يضبط عنوان API العام في إعدادات البناء. تبقى أسرار Google والدفع والتوقيع على الخادم فقط. اختبر جلسة الدخول والملف الشخصي والإيداع والسحب من هاتف فعلي بعد كل إصدار.

يلزم تفعيل نسخ احتياطية خارجية أو خدمة نسخ احتياطية لدى مزود قاعدة البيانات مع تشفير وصلاحيات وصول محدودة ومدة احتفاظ محددة. اختبر الاستعادة إلى قاعدة بيانات منفصلة، وتأكد من استرجاع المستخدمين ومعرفاتهم والمحافظ والحجوزات والطلبات والمعاملات والتدقيق والوسائل والإشعارات وجداول الهوية؛ لا تستعد نسخة مباشرة فوق قاعدة العملاء الحالية. لم يجر إنشاء جدولة نسخ أو نسخة كاملة من بيانات العملاء في هذا التحديث، لذلك لا توصف النسخ بأنها مفعّلة.

تحتاج مراقبة الجهوزية إلى خدمة مُهيأة وتنبيه للمالك وخطة استجابة عند الأعطال. لا توجد مراقبة تلقائية مفعلة أو خدمة إعادة تشغيل مستقلة جديدة في هذا التحديث. لا تستخدم طلبات دورية لإبقاء استضافة on-demand مستيقظة كبديل لوضع استضافة مناسب.

## عند تعطل الخادم

افحص نتيجة `/api/ready` وسجل الخطأ دون نشر أسرار، ثم حالة قاعدة البيانات وإعدادات البيئة والإصدار. أعد محاولة العملية المالية بنفس operationId عند غموض النتيجة، ولا تعالج فشل الشبكة بإضافة الرصيد يدويًا مرة أخرى. استرجاع نسخة من كود التطبيق لا يعني استرجاع قاعدة البيانات؛ راجع توافق migrations قبل الرجوع إلى كود قديم. يحتفظ Git بإصدارات الكود، لكنه ليس نسخة احتياطية من أموال العملاء أو بياناتهم.
