# Flotex EGP — مشروع هاتف مستقل داخل Manus

هذه نسخة مستقلة مستوردة من تطبيق **Flotex EGP** مبنية على Expo Router وReact Native وTypeScript، مع خادم Express/tRPC وقاعدة MySQL خاصة بمشروع Manus هذا. بقي أرشيف المصدر المرفق دون تعديل؛ لم تُنقل قاعدة بياناته أو أسراره إلى المشروع الجديد. مستندات `docs/source-*` وسجل الإنجاز الأقدم في TODO منقولة من المصدر للاطلاع التاريخي، ولا تثبت حالة النسخة الجديدة.

تحتفظ النسخة بأصول التطبيق وتصميمه ومساراته الحالية، وتضيف أدوات الترتيب والإدارة المطلوبة. بريد الإدارة المعتمد في المشروع هو `dyblhwyty@gmail.com`، ويُحسم دور الحساب على الخادم عند التسجيل/المصادقة.

قارنت ملفات التطبيق وأصوله مع ZIP: جميع ملفات `app/` الـ45 وموارد `assets/` الـ28 موجودة. تستعيد الرئيسية كتالوج الخدمات التسع الأصلي كاملًا، وتبقى بطاقات المحفظة الست كما في المصدر؛ ترتيب الإدارة يؤثر على الأزرار الأربعة المطلوبة فقط.

## ما يتضمنه المشروع

- ترتيب أزرار الإيداع والسحب وإرسال الأموال والادخار من لوحة الإدارة، مع جلب الترتيب المحفوظ من الخادم تلقائيًا؛ تبقى الخدمات التسع الأصلية ظاهرة، ولا تنتقل الخدمات الخمس الأخرى من مواقعها.
- التحكم في ظهور جميع خدمات الرئيسية والمحفظة، بما في ذلك الأزرار المساعدة، مع إظهار كل العناصر افتراضيًا وعدم حذف أي صفحة أو مسار.
- إعدادات حقول مستقلة للإيداع والسحب لكل طريقة دفع، تشمل الإضافة والحذف والتسمية والنوع والإلزام والإخفاء والترتيب ومعاينة النموذج قبل الحفظ.
- مراجعة الطلبات وأرشفتها بعد القرار. طلب سحب 1xBet يتضمن كود السحب ومعرّف المستخدم؛ اعتماد الطلب يضيف المبلغ إلى محفظة المستخدم مرة واحدة مع تسجيل الحركة. يبقى السحب النقدي المعتاد وفق تدفقه الأصلي.
- لوحة لإظهار/إخفاء الأزرار العامة، وتخصيص مستقل داخل ملف المستخدم، مع سجل تدقيق يبين المسؤول والوقت والسبب إن وجد. لا يؤدي إخفاء الزر إلى حذف المسار البرمجي أو تغيير دفتر الأموال.
- إدخال مبلغ الادخار بلوحة رقمية ودعم الأرقام العشرية.
- عرض آخر فتح وآخر نشاط ناجح في ملف العميل بتوقيت `Africa/Cairo`، مع حماية استعلامات النشاط بصلاحية الإدارة.

## فتح ومعاينة الهاتف

افتح هذا المشروع من مساحة مشاريع Manus لمعاينة التطبيق وقراءة الملفات وتعديلها. لمعاينة الهاتف:

1. من Dashboard لهذا المشروع استخدم **Connect Expo** لمزامنة بيئة Expo وفتح رمز QR.
2. ثبّت **Expo Go** على هاتفك، وسجّل الدخول بحساب Expo نفسه إن طلب ذلك، ثم امسح الرمز من Expo Go.
3. معاينة Expo Go وسيلة تشغيل للتطوير وليست ملف تثبيت Android مستقلًا.

لم يُنشأ APK/AAB ولم يُنشر التطبيق للعامة. إنشاء نسخة تثبيت مستقلة يكون من إجراء **Build** في Dashboard بعد ضبط عنوان API إصدار ثابت؛ عنوان معاينة Manus مؤقت وغير مناسب لتطبيق موزع. لم تُرسل رسالة بريد اختبارية أو تُنفّذ حركة مالية حية.

## الإعدادات والخصوصية

يجب إعداد `AUTH_OTP_APP_PASSWORD` في مخزن أسرار Manus المحمي للنسخة الجديدة، لا في الملفات أو Git. لا تضع كلمات مرور أو متغيرات بيئة سرية في الشيفرة أو سجل الطرفية. قاعدة بيانات المشروع منفصلة عن المشروع الأصلي؛ لا ينقل الأرشيف حسابات أو أرصدة سابقة، ويجب تطبيق ترحيلاتها قبل استخدامها.

إعدادات الإيداع والسحب مستقلة، ويجب عدم إدخال بيانات دفع حقيقية عند استخدام بيئة الاختبار. مراجعات الأموال الفعلية تحتاج حسابات وإجراءات تشغيل مناسبة قبل النشر.

عند تشغيل الإصدار، يتحقق `pnpm start` من حالة الترحيلات دون تطبيقها تلقائيًا. قبل أي تعديل على قاعدة إنتاج قائمة، خذ نسخة احتياطية صالحة واختبر الاستعادة وخطة الرجوع، ثم راجع SQL وشغّل الترحيل صراحةً. الفحص النصي للترحيلات ليس ضمانًا لاكتشاف كل تغيير قد يسبب فقد البيانات. قاعدة التطوير وبيانات الإصدار في Manus مشتركة بعد النشر.

## أوامر التطوير والفحص

```bash
pnpm dev          # خادم API وMetro/معاينة الويب
pnpm check        # فحص TypeScript
pnpm lint         # قواعد lint
pnpm build        # تصدير الويب وتجميع خادم API
pnpm db:migrate   # تشغيل migrations الآمنة بعد مراجعتها
pnpm test         # مجموعة Vitest؛ اختبارات قاعدة البيانات تتطلب DB محلية معزولة
```

لا تشغّل اختبارات التكامل على قاعدة Manus المشتركة؛ يجب أن تستخدم قاعدة اختبار محلية على loopback باسم `flotex_test_*`. تفاصيل المكونات في `app/`, `components/`, `server/`, `shared/`, `drizzle/`, و`tests/`.
